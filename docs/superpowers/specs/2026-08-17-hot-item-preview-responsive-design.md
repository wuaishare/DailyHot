# DailyHot 首页热点悬浮预览自适应设计

## 背景

首页是高密度热榜扫描界面，Hover Preview 的任务不是承载完整详情，而是在不破坏榜单上下文的前提下，帮助用户在约 2 秒内判断一条热点是否值得点击。

当前 Preview 已具备摘要、图片和热度，但图片按原始比例缩放到最大 150×150。竖图会把卡片高度撑高，而文本区内容不足时形成大片空白；不同图片比例还会让定位高度估算与实际视觉占用波动过大。

## 目标

1. 图片不能决定整张 Preview 的高度。
2. 横图、方图、竖图都使用稳定的媒体槽，并允许轻量裁切。
3. Preview 尺寸应随媒体形态收敛，避免无意义大卡片。
4. 定位算法必须使用最终展示尺寸，避免视觉尺寸与碰撞检测不一致。
5. 保持现有 Hover Intent、图片失败回退和“无增量信息不显示”的原则。
6. 顺手降低重复 Pointer/Mouse 事件带来的定时器抖动，并提升热度数字的可读性。

## 方案

### 图片分档

根据图片 naturalWidth / naturalHeight：

- `portrait`：ratio < 0.8，媒体槽 84×112，Preview 约 390px。
- `square`：0.8 <= ratio < 1.25，媒体槽 104×104，Preview 约 410px。
- `landscape`：ratio >= 1.25，媒体槽 132×88，Preview 约 440px。

极端长图与超宽图不再按原始比例继续缩放，而是进入对应媒体槽，通过 `object-fit: cover` 保持布局稳定。

图片加载失败时继续降级为纯文本 Preview，并重新按当前目标元素和原 placement 定位；如果没有摘要等增量信息，则关闭 Preview。

### 内容密度

- 标题最多 2 行。
- 摘要最多 3 行，减少 Hover 面板高度和遮挡。
- 热度对纯数字做中文量级格式化，例如 `7523147 -> 752.3万`；非纯数字保持原样，避免误解释平台自定义热度字符串。
- 纯图片 + 标题时，文本区在媒体槽高度内垂直居中，消除竖图旁的大面积下方空白感。

### 定位

定位仍按 `right -> left -> below -> above` 的优先顺序，并保持图片失败时的 preferred placement。

Preview 宽度和高度都从最终媒体槽计算，而不是从图片自然缩放结果计算。碰撞检查、viewport clamp 与视觉展示使用同一组尺寸。

### 交互

- 桌面端仅使用 pointer enter / leave，避免同时绑定 mouseenter + pointerenter 导致同一次进入被触发两次。
- 保留键盘 focusin / focusout。
- 保留 180ms 打开延迟。
- 滚动、拖拽和全局关闭行为保持不变。

### 视觉细节

- 阴影收敛，减少 Preview 对榜单主体的视觉压迫。
- 动画继续使用短时淡入和轻微位移。
- 媒体槽统一圆角和弱背景，避免图片比例差异破坏整体节奏。

## 验收标准

- 竖图不再生成大面积空白 Preview。
- 横图、方图、竖图的卡片尺寸稳定，且不因自然尺寸过大而撑开。
- 图片加载失败后卡片不会发生异常横向漂移。
- 同一次鼠标进入不会被 mouse/pointer 双事件重复调度。
- 热度纯数字显示为更易读的万/亿格式。
- 无摘要且图片不可用时不显示 Preview。
- `npm run build` 成功。
