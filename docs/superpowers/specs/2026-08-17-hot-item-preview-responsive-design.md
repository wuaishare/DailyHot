# DailyHot 首页热点悬浮预览自适应设计

## 背景

首页是高密度热榜扫描界面，Hover Preview 的任务不是承载完整详情，而是在不破坏榜单上下文的前提下，帮助用户在约 2 秒内判断一条热点是否值得点击。

当前 Preview 已具备摘要、图片和热度，但图片按原始比例缩放到最大 150×150。竖图会把卡片高度撑高，而文本区内容不足时形成大片空白；不同图片比例还会让定位高度估算与实际视觉占用波动过大。

## 目标

1. 图片不能决定整张 Preview 的高度。
2. 横图、方图、竖图都使用稳定的媒体槽，并允许轻量裁切。
3. Preview 尺寸应随媒体形态收敛，避免无意义大卡片。
4. 定位算法必须使用最终展示尺寸，避免视觉尺寸与碰撞检测不一致。
5. 保持现有 Hover Intent、图片失败回退和“无增量信息不显示”的原则。
6. 顺手降低重复 Pointer/Mouse 事件带来的定时器抖动，并提升热度数字的可读性。

## 方案

### 图片分档与双尺寸体系

根据图片 naturalWidth / naturalHeight 继续分为 `portrait` / `square` / `landscape`，但同一种图片根据 Preview 状态使用两套尺寸：

- **有摘要的图文模式**：portrait 96×128、square 112×112、landscape 148×96。对应 Preview 宽度约 420 / 430 / 460px，图片只承担辅助信息角色。
- **无摘要的纯媒体模式**：portrait 168×224、square 200×200、landscape 240×144。图片成为主要增量信息，尺寸足够辨认人物、海报文字和新闻画面。

极端长图与超宽图进入对应固定媒体槽，通过 `object-fit: cover` 轻量裁切。竖图视觉焦点适当上移，降低人物头部被裁掉的概率。

图片加载失败时：有摘要则降级为纯文本 Preview 并保持原 placement；没有摘要则直接关闭 Preview。

### 状态矩阵与内容密度

- **有摘要 + 有图片**：摘要 + 热度 + 右侧图片，保留 12px 内边距；摘要最多 3 行。
- **有摘要 + 无图片**：纯文本摘要 + 热度，保留紧凑内边距。
- **无摘要 + 有图片**：纯媒体卡片。图片直接贴合卡片边缘，外层 `padding: 0`；如果有热度，以左下角半透明 Overlay 胶囊覆盖在图片上，不再单独占一行。
- **无摘要 + 无图片**：即使只有热度也不显示 Preview，因为没有足够的增量信息值得打断扫榜流程。
- Preview 始终不重复显示榜单标题。
- 热度对纯数字做本地化 compact 格式化，例如 `7523147 -> 752.3万`；非纯数字保持原样。

### 定位

定位仍按 `right -> left -> below -> above` 的优先顺序，并保持图片失败时的 preferred placement。

Preview 宽度和高度都从最终媒体槽计算，而不是从图片自然缩放结果计算。碰撞检查、viewport clamp 与视觉展示使用同一组尺寸。

### 交互

- 桌面端仅使用 pointer enter / leave，避免同时绑定 mouseenter + pointerenter 导致同一次进入被触发两次。
- 保留键盘 focusin / focusout。
- 保留 180ms 打开延迟。
- 滚动、拖拽和全局关闭行为保持不变。

### 视觉细节

- 阴影收敛，减少 Preview 对榜单主体的视觉压迫。
- 动画继续使用短时淡入和轻微位移。
- 媒体槽统一圆角和弱背景，避免图片比例差异破坏整体节奏。

## 验收标准

- 有摘要时图像大小适中，不抢占正文；无摘要时图片明显大于图文模式，能够看清新闻主体。
- 纯媒体模式取消内容内边距，图片直接形成卡片主体，热度以 Overlay 呈现，不再产生额外空白。
- 横图、方图、竖图都使用稳定尺寸，不因自然尺寸极端而撑开或缩得过小。
- 图片加载失败后卡片不会发生异常横向漂移。
- 同一次鼠标进入不会被 mouse/pointer 双事件重复调度。
- 热度纯数字显示为更易读的万/亿格式。
- Preview 内不再重复榜单标题；无摘要且无图片时，即使存在热度也不显示 Preview。
- `npm run build` 成功。
