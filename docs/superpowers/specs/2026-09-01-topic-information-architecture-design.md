# 专题信息架构重构设计

## 目标

把现有专题从分类附属入口升级为一级产品能力，并减少专题页页头与筛选区的无效占高。

第一阶段只处理已成熟的两个专题：

- 羊毛：红包、优惠券、外卖/闪购券、打车券、免单/赠品及其它消费福利。
- 游戏折扣：Steam、Epic、GOG、小黑盒、GG.deals、喜加一等免费、史低、低价与高折扣机会。

吃瓜与 AI 专题只注册为后续目标，不上线空入口。

## 信息架构

新增共享 Topic Registry，作为专题名称、路由、可见状态、排序、SEO 入口标签的单一真源。Header、专题切换栏和后续 `/topic` 专题中心均消费该注册表。

Header 桌面端增加一级“专题”入口，打开下拉菜单直接进入羊毛或游戏折扣；移动端菜单同步增加专题分组。用户不再需要先进入分类再二次点击专题。

两个专题页面顶部使用同一套紧凑 Topic Switcher：羊毛｜游戏折扣。切换保持当前语言前缀。
## 专题页面布局

取消游戏专题现有独立大 Hero 的两段式占高。专题首屏统一为：

1. Topic Switcher + 当前专题标题/简短状态。
2. 搜索、结果数、多源确认/即将结束、刷新。
3. 类型、来源、排序等筛选。
4. 紧接实时列表。

羊毛专题采用同一骨架，但保留其平台、时间和来源健康状态等专有筛选。共享的是框架与密度，不强行统一不同业务字段。

桌面端目标是在 1440px 首屏明显看到更多有效列表内容；移动端所有横向控制保持内部横滑，不产生页面级横向溢出。

## 分类边界

游戏优惠 Source 不再归入羊毛分类。Steam、Epic、GOG、小黑盒、GG.deals 等只属于“游戏”分类，并由游戏折扣专题聚合。

IT之家喜加一若内容主体是游戏免费领取，则归游戏；非游戏福利后续由内容级分类器处理，不依靠 Source 整体双归属。

羊毛专题后端/前端不再将游戏折扣作为 `game` 意图核心入口，避免与游戏折扣专题争夺 SEO 和用户心智。
## 兼容、SEO 与刷新

保留现有 `/topic/wool` 与 `/topic/game-deals` URL，不做破坏性重定向。五语言 canonical/hreflang 与 route shell 继续生成。

专题切换、筛选与刷新不得触发 Document reload；继续复用现有 AJAX refresh generation。专题切换本身是正常 SPA 路由导航。

SEO 文案明确拆分：羊毛不再主打 Steam/Epic/史低关键词；游戏折扣专注免费游戏、史低、低价、平台折扣等搜索意图。

## 验收

- Header 桌面/移动端均能一级进入两个专题。
- 两个专题都有一致的专题切换栏。
- `/category/wool` 不再展示游戏折扣 Source；`/category/games` 保持完整。
- 羊毛专题实时流不再混入普通游戏折扣。
- 1440px 与 390px 无页面级横向溢出、无 pageerror。
- i18n audit、production build、route-shell 生成、git diff check 通过。
- 搜索/筛选/刷新仍为 AJAX，无 Document 请求。

## 后续目标

第二阶段单独调研和设计“吃瓜”专题；第三阶段单独调研和设计“AI 热点”专题。两者在数据源、聚类与 SEO 方案成熟前不展示占位入口。
