# 热榜徽标静态灾备

第三方热榜徽标仍优先使用平台官方 CDN。DailyHot 只保存一份静态灾备，不让 WP Better Trends 商业 API 代理或托管图片流量。

当前已确认并备份的平台：

- 抖音：21 个原生徽标，包含 48×48 的「直播」动态 GIF。
- 百度：`新 / 热 / 沸` 3 个当前或历史已观测官方图标。
- 快手：`新 / 独家 / 置顶` 3 个当前已观测官方图标。
- 今日头条：`热 / 新 / 现场 / 新进展 / 辟谣 / 解读` 6 个官方图标。
- 知乎：`热 / 新 / 沸` 3 个 App 热榜官方图标。

微博当前进入统一 badge 契约的是文字语义，没有远程 `iconUrl`，因此不制造图片备份；后续上游真正返回官方图片时再纳入。

## 运行规则

1. 前端始终先加载 API 返回的官方 `iconUrl`。
2. 仅当该 URL 能明确识别为对应平台官方资源，且加载失败时，才切换到 `/ico/ranking-badges/<provider>/...`。
3. 灾备文件再次失败时退化为 badge 文本，不影响榜单数据与标题。
4. 不根据通用 `sourceCode` 单独判断平台，避免不同平台编号碰撞导致串图。
5. 静态灾备由 DailyHot/Vercel CDN 承担；Trends 只传输数据契约。

## 更新规则

发现新的官方 badge code / label / iconUrl 时，先核对平台语义与文件内容，再保存原图并扩充映射。若同一 code 的官方图形发生变化，应替换灾备文件；DailyHot 构建阶段的静态资源 content hash 会负责缓存失效。
